# 客户端框架

## 设计思想

客户端采用**分层架构**，从底到上依次为：Core（核心服务）、Framework（通用框架）、业务层。各层通过事件系统和接口解耦，支持模块热插拔。

核心设计原则：
1. 状态机驱动游戏流程（登录 → 主界面 → 战斗）
2. 全局事件总线解耦模块间通信
3. UI 对象池复用，避免频繁创建销毁

## 架构分层

```
┌─────────────────────────────────────────┐
│ 业务层                                    │
│  ApplicationStatus / UI / Message        │
├─────────────────────────────────────────┤
│ 框架层 (Framework)                        │
│  GlobalEvent / LogicSystem / Utils       │
├─────────────────────────────────────────┤
│ 核心层 (Core)                            │
│  Application / Network / UI / Resource   │
└─────────────────────────────────────────┘
```

## ApplicationStatusManager — 状态机

管理游戏流程状态切换（类似 Unity 的 SceneManager，但更轻量）。

### 状态切换流程

```
ApplicationStatusManager.EnterStatus<NewStatus>()
  ├─ 当前状态.CloseAllUI()     // 关闭所有 UI
  ├─ 当前状态.OnExitStatus()   // 清理逻辑、移除事件监听
  ├─ 获取或创建 NewStatus 实例（有缓存）
  ├─ NewStatus.InChangeScene() // 协程：加载场景
  └─ NewStatus.OnEnterStatus() // 初始化新状态、打开 UI、注册事件
```

### IApplicationStatus 接口

```csharp
abstract class IApplicationStatus {
    void OnEnterStatus()       // 进入状态：注册事件、打开UI
    void OnExitStatus()        // 退出状态：清理事件
    void OnUpdate()            // 每帧更新
    IEnumerator InChangeScene() // 场景加载协程

    // UI 管理（状态跟踪其打开的所有 UI）
    T OpenUI<T>()
    void CloseUI<T>()
    void CloseAllUI()
}
```

### 状态实例

```
MainMenuStatus:
  ├─ OnEnterStatus(): 打开 MainWindow，注册登录/匹配消息监听
  ├─ 发送 Login 消息
  ├─ 收到匹配成功 → EnterStatus<GameStatus>()
  └─ OnExitStatus(): 移除所有消息监听

GameStatus:
  ├─ OnEnterStatus(): 初始化 World，打开战斗 UI
  ├─ OnUpdate(): 驱动 WorldManager
  └─ OnExitStatus(): 销毁 World
```

## GlobalEvent — 全局事件系统

三种事件模式，适用于不同场景：

### 基于 Enum（传统方式）

```csharp
GlobalEvent.AddEvent(MyEvent.PlayerDie, OnPlayerDie);
GlobalEvent.DispatchEvent(MyEvent.PlayerDie, playerID);
GlobalEvent.RemoveEvent(MyEvent.PlayerDie, OnPlayerDie);
```

### 基于 String（灵活方式）

```csharp
GlobalEvent.AddEvent("player_die", handler);
GlobalEvent.DispatchEvent("player_die", args);
```

### 基于 Type（强类型，推荐用于网络消息）

```csharp
GlobalEvent.AddTypeEvent<PlayerLoginMsg_c>(OnLoginResponse);
GlobalEvent.DispatchTypeEvent<PlayerLoginMsg_c>(msg);
GlobalEvent.RemoveTypeEvent<PlayerLoginMsg_c>(OnLoginResponse);
```

**特性：**
- 支持一次性事件（isUseOnce=true，触发后自动清除）
- 多监听者（委托链）
- 异常捕获不影响其他监听者

## UIManager — UI 系统

### UI 生命周期

```
OnInit    → 首次创建时
OnOpen    → 每次打开时
OnShow    → 显示时
OnRefresh → 主动刷新
OnHide    → 隐藏时
OnClose   → 关闭时
DestroyUI → 销毁时
```

### 打开 UI

```
UIManager.OpenUIWindow<T>():
  ├─ 检查 s_hideUIs 缓存
  │   ├─ 有 → 从隐藏列表取出复用
  │   └─ 无 → ResourceManager.Load + Instantiate + OnInit
  ├─ 加入 s_UIs 活跃列表
  ├─ UISystemEvent.Dispatch(OnOpen)
  ├─ 调用 UI.OnOpen()
  ├─ 设置层级（Canvas sortingOrder）
  └─ 播放进入动画
```

### 关闭 UI

```
UIManager.CloseUIWindow<T>():
  ├─ 从 s_UIs 活跃列表移除
  ├─ 清除所有事件监听
  ├─ 播放退出动画
  ├─ UISystemEvent.Dispatch(OnClose)
  ├─ 调用 UI.OnClose()
  └─ 加入 s_hideUIs 缓存
```

### UIBase 控件获取

UI 基类提供快速获取子控件的方法（带缓存）：

```csharp
// 在 Inspector 中配置 m_objectList
GetImage("imageName")
GetText("textName")
GetButton("btnName")
GetSlider("sliderName")
GetToggle("toggleName")
GetInputField("inputName")
```

### UISystemEvent

系统级 UI 事件分发：

```
UISystemEvent.Dispatch(UIWindowBase ui, UIEvent eventType)
  ├─ 遍历 s_allUIEvents 全局监听
  └─ 遍历 s_singleUIEvents[ui] 特定UI监听
```

## NetworkManager — 网络管理

### 消息接收流程

```
Network Thread:
  Socket 接收数据 → ReceviceMessage(NetWorkMessage)
      → 加入 s_messageList 队列

Main Thread (每帧):
  NetworkManager.Dispatch()
    ├─ 遍历 s_messageList
    └─ InputNetworkEventProxy.DispatchMessageEvent(msg)
        ↓
  ProtocolAnalysisService (已注册监听)
    └─ 反序列化 → GlobalEvent.DispatchTypeEvent<T>(msg)
        ↓
  业务逻辑（ApplicationStatus 中注册的回调）
```

### 消息发送

```
ProtocolAnalysisService.SendCommand(msg)
  → 序列化为 ByteArray
  → NetworkManager.SendMessage(data)
  → Socket 发送
```

## ResourceManager — 资源管理

双模式加载：

| 模式 | 路径 | 用途 |
|------|------|------|
| Resources.Load | Assets/Resources/ | 开发环境 |
| AssetBundle | StreamingAssets/ | 发布环境 |

```csharp
ResourceManager.Load<T>(name)       // 同步加载
ResourceManager.LoadAsync(name, cb) // 异步加载
```

## GlobalLogicManager — 全局逻辑

管理需要在所有状态下持续运行的逻辑（如心跳）：

```csharp
IApplicationGlobalLogic {
    void Init()
    void Update()  // 每帧调用
}

// 示例：HeartBeatService - 每30秒发送心跳
```

## 完整消息处理调用链

```
服务端发送消息
    ↓
NetworkManager (网络线程接收)
    ↓
s_messageList 队列
    ↓
Dispatch (主线程每帧)
    ↓
InputNetworkEventProxy
    ↓
ProtocolAnalysisService (反序列化 + 按消息名分发)
    ↓
GlobalEvent.DispatchTypeEvent<T>
    ↓
ApplicationStatus 中的回调方法
    ↓
业务逻辑处理 (切换状态 / 更新UI / ...)
```
