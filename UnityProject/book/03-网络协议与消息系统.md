# 网络协议与消息系统

## 设计思想

项目采用**自定义二进制协议 + 代码生成**的方案。协议用类 Protobuf 的文本格式定义，通过工具自动生成序列化/反序列化代码和消息分发逻辑，避免手写样板代码。

核心设计选择：
1. 二进制协议（非 JSON/Protobuf），极致性能
2. 代码生成而非运行时反射，编译期确定所有消息处理
3. Dictionary<string, object> 作为中间表示，统一序列化接口

## 协议定义格式

### ProtocolInfo.txt

```
message m_affirmmsg_s {
    required int32 frame = 1;
    required int32 time = 2;
    required int32 id = 3;
}

message syncvector3 {
    required int32 x = 1;
    required int32 y = 2;
    required int32 z = 3;
}

message commandinfo {
    required syncvector3 moveDir = 1;
    required syncvector3 skillDir = 2;
    required int32 element1 = 3;
    required int32 element2 = 4;
    required bool isFire = 5;
    required int32 id = 6;
}

message m_commandmsg_s {
    required int32 frame = 1;
    repeated commandinfo commList = 2;
    required int32 servertime = 3;
}
```

**语法规则：**
- `message 消息名 { ... }` — 定义消息
- `required 类型 字段名 = 序号;` — 必需字段
- `repeated 类型 字段名 = 序号;` — 数组字段
- 支持类型：int32、int16、int8、double、bool、string、自定义消息名

**命名约定：**
- `_s` 后缀 — 服务端到客户端
- `_c` 后缀 — 客户端到服务端
- 无后缀 — 通用结构体

### MethodInfo.txt

消息号映射表，格式为 `ID,名称`：

```
1,GameSync          // 模块 ID
2,SyncModule
201,affirmmsg       // 消息 ID = 模块号*100 + 序号
202,changecomponentmsg
203,commandmsg
204,destroyentitymsg
205,pursuemsg
206,startsynmsg
207,syncentitymsg
```

## 消息包格式

```
[0-1]  消息总长度（2字节，大端序）
[2]    模块号（1字节）= methodIndex / 100
[3-4]  消息号（2字节，大端序）= methodIndex
[5+]   消息体数据
```

## 序列化规则

### 基本类型

| 类型 | 字节数 | 编码方式 |
|------|--------|---------|
| int32 | 4 | 大端序 |
| int16 | 2 | 大端序 |
| int8 | 1 | 直接写入 |
| bool | 1 | 0/1 |
| double | 8 | IEEE754 |
| string | 2+N | 2字节长度 + UTF-8字节 |

### 复合类型

**repeated（数组）：**
```
[数组长度: 2字节] [数据总大小: 4字节] [元素1] [元素2] ...
每个元素前有 4 字节的元素大小
```

**嵌套对象：**
```
[对象大小: 4字节] [字段1] [字段2] ...
递归序列化
```

### 生成工具

| 工具 | 用途 |

| Tool_GenerateAnalysisCode | 从 ProtocolInfo.txt 生成 ProtocolAnalysisService.cs |
| CSharp2Protocol | 从 C# 消息类生成 ProtocolInfo.txt |

### 生成产物

1. **ProtocolMessageClass.cs** — 所有消息的 C# 类定义
2. **ProtocolAnalysisService.cs** — 消息的发送/接收/分发代码

### ProtocolAnalysisService 结构

```csharp
// 发送方法（为每种消息类型生成）
public static void SendMsg(session, IProtocolMessageInterface msg)
{
    switch(msg.GetType().Name.ToLower())
    {
        case "startsynmsg": SendStartSyncMsg(session, (StartSyncMsg)msg); break;
        case "commandmsg": SendCommandMsg(session, (CommandMsg)msg); break;
        // ...
    }
}

// 接收分发（为每种消息类型生成）
public static void AnalysisAndDispatchMessage(session, ProtocolRequestBase cmd)
{
    switch(cmd.Key)
    {
        case "affirmmsg": ReceviceAffirmMsg(session, cmd); break;
        case "commandmsg": ReceviceCommandMsg(session, cmd); break;
        // ...
    }
}
```

## 消息收发流程

### 服务端接收

```
TCP Socket 数据到达
    ↓
ProtocolReceiveFilter.Filter()  — 分包（按长度字段）
    ↓
Analysis() — 解析协议头：模块号、消息号
    ↓
AnalysisData() — 递归反序列化消息体 → Dictionary<string, object>
    ↓
ProtocolRequestBase { Key = "affirmmsg", m_data = {...} }
    ↓
ProtocolAnalysisService.AnalysisAndDispatchMessage()
    ↓
ReceviceXxxMsg() — 从 Dictionary 重建消息对象
    ↓
EventService.DispatchTypeEvent() — 派发到业务逻辑
```

### 服务端发送

```
业务逻辑创建消息对象 (如 CommandMsg)
    ↓
ProtocolAnalysisService.SendMsg(session, msg)
    ↓
SendCommandMsg() — 消息字段写入 Dictionary<string, object>
    ↓
session.SendMsg(key, data) — SessionSendExpand
    ↓
GetSendByte() — 序列化为字节数组
    ↓
构建包：[长度][模块号][消息号][消息体]
    ↓
session.Send(buffer) — 发送
```

### 客户端接收

```
NetworkManager 接收原始数据
    ↓
消息入队 s_messageList
    ↓
主线程 Dispatch：InputNetworkEventProxy.DispatchMessageEvent
    ↓
ProtocolAnalysisService（已注册的监听）
    ↓
GlobalEvent.DispatchTypeEvent<T>(msg) — 派发到业务层
```

### 客户端发送

```
ProtocolAnalysisService.SendCommand(msg)
    ↓
序列化为 Dictionary → ByteArray
    ↓
NetworkManager.SendMessage(data) → Socket 发送
```

## ByteArray 核心类

低级字节操作工具：

```csharp
// 读取
int ReadInt()        // 4字节大端
short ReadShort()    // 2字节大端
byte ReadInt8()      // 1字节
bool ReadBoolean()   // 1字节
double ReadDouble()  // 8字节
string ReadString()  // 2字节长度 + UTF-8

// 写入
WriteInt(int)
WriteShort(short)
WriteInt8(byte)
WriteBoolean(bool)
WriteDouble(double)
WriteString(string)
```
