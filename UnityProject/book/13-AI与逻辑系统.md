# AI 与逻辑系统

## 结论

本项目**没有使用传统的行为树或有限状态机来实现 AI**。项目中存在三套相关但不同的系统：

| 系统 | 用途 | 是否用于 AI |
|------|------|------------|
| LogicSystem（节点式逻辑） | 游戏流程控制（地图事件、物品刷新） | 否，用于关卡逻辑 |
| CharacterStatus（角色状态） | 角色行为表现（移动、攻击、死亡） | 否，用于动画/表现 |
| CommandRouteService（命令路由） | 命令分发执行 | 否，用于同步命令 |

BehaviorTree 目录存在但为空，StateMachineEditor 仅是一个可视化编辑框架，不涉及 AI 决策。

当前项目的战斗逻辑完全由**玩家输入驱动**（通过 CommandComponent），没有实现 AI 自主决策。服务端有 `AIComponentBase` 基类定义但无具体实现。

## LogicSystem — 节点式逻辑系统

### 设计思想

LogicSystem 是一个**事件-条件-动作（ECA）**的流程控制框架，用于编排游戏关卡逻辑（如倒计时刷物品、结束判定）。它不是 AI 系统，而是关卡脚本的数据驱动替代方案。

### 执行模型

```
Event 触发 → Condition 检查（全部通过） → Action 执行 → 子节点初始化
```

### 核心架构

```
LogicSystemManager (全局管理)
 └─ LogicRuntimeMachine (运行时实例)
     ├─ internalValueList (内部变量)
     ├─ LogicObject[] (节点数组)
     │   ├─ events: EventComponentBase[]      (触发条件)
     │   ├─ conditions: ConditionComponentBase[] (前置条件)
     │   ├─ actions: ActionComponentBase[]    (执行动作)
     │   └─ childObjects: int[]              (子节点 ID)
     └─ 子逻辑状态机 (嵌套)
```

### LogicObject 数据结构

```csharp
public class LogicObject
{
    public string name;                  // 节点名
    public int id;                       // 节点 ID
    public EventsObject events;          // 触发事件列表
    public ConditionsObject conditions;  // 条件列表
    public ActionsObject actions;        // 动作列表
    public List<int> childObjects;       // 子节点 ID
}
```

### 事件类型

| 事件类 | 说明 |
|--------|------|
| Event_Timer_Countdown | 倒计时完成时触发 |
| Event_Value_InternalValueChange | 内部变量变化时触发 |
| Event_EventComponent | 通用事件 |

### 条件类型

| 条件类 | 说明 |
|--------|------|
| Condition_Value_ValueCompare | 比较两个值的大小关系 |

### 动作类型

| 动作类 | 说明 |
|--------|------|
| Action_GameScene_PutObjects | 在场景中放置物品 |
| Action_Game_GameFinish | 游戏结束 |
| Action_Player_CreatePositions | 创建玩家出生点 |
| Action_System_AddChildLogicMachine | 添加子逻辑状态机 |
| Action_Value_Control | 数值计算（加减乘除） |
| Action_Debug_Log | 调试日志输出 |

### 配置文件示例

路径：`Assets/Resources/LogicObjects/MapLogicObjects/mapLogic_0.txt`

```json
{
  "logicObjs": [
    {
      "name": "开始",
      "id": 0,
      "events": {},
      "conditions": {},
      "actions": {},
      "childObjects": [2, 3]
    },
    {
      "name": "物品放置",
      "id": 1,
      "events": [{
        "ScriptName": "Event_Timer_Countdown",
        "timeCount": 5
      }],
      "actions": [{
        "ScriptName": "Action_GameScene_PutObjects",
        "itemType": 0
      }]
    }
  ],
  "startId": 0
}
```

### 执行流程

```
LogicSystemManager.Init()
  └─ 加载 mapLogic_0.txt
      └─ 创建 LogicRuntimeMachine
          ├─ 解析所有 LogicObject
          ├─ 初始化 startId 节点
          │   ├─ 注册 Events（如倒计时）
          │   └─ 初始化子节点
          └─ 运行循环:
              ├─ Event_Timer_Countdown 计时到达
              ├─ 检查 Conditions（全部满足？）
              ├─ 执行 Actions（放置物品）
              └─ 初始化 childObjects
```

## CharacterStatus — 角色状态系统

### 设计思想

角色状态系统管理角色的**表现行为**（动画、特效），不做决策。状态由外部命令驱动切换。

### 状态列表

```csharp
public class CharacterBase
{
    public MoveStatus m_moveStatus;        // 移动
    public AttackSatus m_atkStatus;        // 攻击
    public SkillStatus m_skillStatus;      // 技能释放
    public DieStatus m_dieStatus;          // 死亡
    public HurtStatus m_hurtStatus;        // 受击
    public BlowFlyStatus m_blowFlyStatus;  // 击飞
    public BuffStatus m_buffStatus;        // Buff
}
```

### 状态切换方式

角色状态不是自主切换的，而是由命令系统驱动：

```
CommandRouteService 收到命令
  ↓
CharacterManager.ReceviceCharacterCmd(cmd)
  ↓
根据命令类型切换状态:
  MoveCmd    → character.m_moveStatus.Enter()
  SkillCmd   → character.m_skillStatus.Enter()
  DieCmd     → character.m_dieStatus.Enter()
  AttackCmd  → character.m_atkStatus.Enter()
```

## CommandRouteService — 命令路由

### 设计思想

命令路由是 Game 层的命令分发中枢，将帧同步层的命令翻译为角色行为。这是一套独立于帧同步 ECS 的角色表现系统。

### 命令类型

**同步命令（SyncCommandBase）** — 有时间戳，按帧执行：
- CreateCharacterCmd：创建角色
- DieCmd：死亡
- DamageCmd：伤害
- ResurgenceCmd：复活

**追赶命令（PursueCommandBase）** — 实时命令，可快进：
- MoveCmd：移动
- SkillCmd：释放技能
- RotationCmd：旋转
- AttackCmd：攻击
- BlowFlyCmd：击飞

### 命令执行流程

```
服务端广播 CommandMsg
  ↓
SyncSystem 接收
  ↓
CommandRouteService.ExecuteSyncCmd(cmd) 或 ExecutePursueCmd(cmd)
  ↓
switch(cmd.type):
  case MoveCmd:
    CharacterManager.GetCharacter(cmd.id).ReceviceCmd(cmd)
      → m_moveStatus.SetMoveDir(cmd.dir)
      → 播放移动动画
  case SkillCmd:
    CharacterManager.GetCharacter(cmd.id).ReceviceCmd(cmd)
      → m_skillStatus.UseSkill(cmd.skillID)
      → 播放技能动画 + 特效
```

### 与帧同步 ECS 的关系

```
帧同步层 (SyncGameLogic / ECS):
  CommandComponent → OperationSystem → MoveSystem → pos 更新
  └─ 纯逻辑，整数运算，确定性

命令路由层 (Game / CommandRouteService):
  CommandMsg → CommandRouteService → CharacterBase → 动画/特效
  └─ 纯表现，浮点运算，客户端独有
```

两者并行工作：ECS 层保证数据同步，命令路由层保证表现效果。

## StateMachineEditor — 状态机编辑器

### 用途

这是一个**可视化编辑器工具**，用于在 Unity Editor 中设计状态机流程图。本身不是运行时 AI 系统。

### 组成

| 文件 | 说明 |
|------|------|
| StateMachineBGGUI | 背景绘制（网格、坐标） |
| MachineStateInputEventController | 输入处理（拖拽、连线） |
| StateMachineEditorWindow | 编辑器主窗口 |

用于可视化编辑 LogicSystem 的节点关系，不涉及运行时逻辑。

## 总结对比

| 方案 | 本项目状态 | 适用场景 |
|------|-----------|---------|
| 行为树 | 空目录，未实现 | 复杂 AI 决策（巡逻、追击、组合技） |
| 有限状态机 | 仅用于角色表现层 | 角色动画状态切换 |
| ECA 节点系统 | LogicSystem，已实现 | 关卡流程控制（计时器、条件触发） |
| 命令驱动 | CommandRouteService，已实现 | 帧同步中的行为分发 |
| AI 决策 | AIComponentBase 空壳 | 预留，未开发 |

本项目是一个**多人对战 Demo**，所有行为由玩家输入驱动，不需要 AI 自主决策。如果要加入 AI 对手（Bot），可以：
1. 在服务端实现 AIComponentBase 的具体子类
2. 在 FixedUpdate 中根据游戏状态生成 CommandComponent
3. 模拟玩家输入注入 ECS 系统
