# 服务端服务层

## 设计思想

服务端采用**服务化架构**，每个业务功能封装为独立的 Service，通过事件机制松耦合通信。主入口 SyncService 继承 SuperSocket 的 AppServer，负责网络通信和服务编排。

服务之间的协作通过事件总线完成，避免硬编码依赖关系。

## 启动流程

```
Program.Main()
  └─ BootstrapFactory.CreateBootstrap()
      └─ bootstrap.Start()
          └─ SyncService.Setup() + OnStarted()

SyncService.Setup():
  ├─ Debug.SetLogger()           // 日志
  ├─ DataBaseService.Init()      // 数据库连接
  ├─ loginService.Init()         // 登录
  ├─ matchService.Init()         // 匹配
  ├─ reConnectService.Init()     // 重连
  ├─ selectCharacterService.Init() // 选角
  ├─ CommandMessageService<CommandComponent>.Init() // 命令同步
  ├─ GameMessageService.Init()   // 游戏消息
  └─ UpdateEngine.Init(50ms)     // 帧更新引擎
```

## 服务模块

### LoginService — 登录服务

**职责：** 处理玩家登录/注册，加载玩家数据。

**调用链：**
```
客户端连接 → OnSessionCreate()
客户端发送 PlayerLoginMsg_s
    ↓
RecevicePlayerLogin(session, msg):
  ├─ playerID = msg.playerID
  ├─ DataBaseService.IsAvailable?
  │   ├─ 是 → 查询 PlayerTable
  │   │   ├─ 存在 → 加载数据到 Player 对象
  │   │   └─ 不存在 → 创建记录，初始化默认数据
  │   └─ 否 → 创建临时 Player 对象
  ├─ session.player = player
  ├─ 发送 PlayerLoginMsg_c（成功/失败）
  └─ 派发 m_service.OnPlayerLogin(player)
```

**Player 数据结构：**
```
Player {
    session: SyncSession
    playerID: string
    nickName: string
    characterID: string (默认 "1")
    OwnCharacter: string
}
```

### MatchService — 匹配服务

**职责：** 管理匹配队列，凑齐玩家后创建游戏世界。

**调用链：**
```
客户端发送 PlayerMatchMsg_s
    ↓
ReceviceMatchMsg(session, msg):
  ├─ msg.isCancel == true → CancelMatch()
  └─ msg.isCancel == false → Match():
      ├─ 加入 matchList
      ├─ 发送 PlayerMatchMsg_c(isMatched=false, predictTime=300ms)
      ├─ matchList.Count >= roomPeopleNum (2人)?
      └─ 满员 → StartGame()

StartGame(Player[]):
  ├─ world = WorldManager.CreateWorld<DemoWorld>()
  ├─ world.IsStart = true
  ├─ world.SyncRule = SyncRule.Status
  ├─ for each player:
  │   ├─ 创建 ConnectionComponent (持有 session)
  │   ├─ 创建 SyncComponent
  │   └─ world.CreateEntityImmediately("Player"+id, conn, sc)
  ├─ 派发 ServiceEventDefine.c_playerJoin
  └─ 发送 PlayerMatchMsg_c(isMatched=true)
```

### SelectCharcterService — 选角服务

**职责：** 处理角色选择和角色购买。

```
客户端发送 PlayerSelectCharacter_s(characterID)
    ↓
ReceviceSelectCharacter():
  ├─ 验证已登录
  ├─ 验证角色在 OwnCharacter 列表中
  ├─ session.player.characterID = characterID
  └─ 发送确认
```

### SettlementService — 结算服务

**职责：** 游戏结束后计算排名和奖励。

```
GameSystem 派发 GameUtils.c_gameFinish
    ↓
SettlementService.OnGameFinish():
  ├─ 获取 RankComponent 排名列表
  ├─ for each rank:
  │   ├─ diamond = totalPlayers - rank
  │   ├─ session.player.Diamond += diamond
  │   └─ 发送 PlayerSettlement_c(rank, score, diamond)
  └─ 清理世界
```

### ReConnectService — 重连服务

**职责：** 处理断线重连，恢复玩家会话。

```
掉线:
OnSessionClose():
  ├─ 保存 ConnectionComponent 到 m_disConnectDict
  └─ 派发 ServiceEventDefine.c_playerExit

重连:
OnPlayerLogin():
  ├─ 检查 m_disConnectDict 有该玩家
  ├─ 恢复 conn.m_session = new_session
  ├─ 派发 ServiceEventDefine.c_playerJoin
  └─ 发送 PlayerMatchMsg_c(isMatched=true)
```

### ShopService — 商店服务

**职责：** 处理角色购买（消耗钻石）。

### GameMessageService — 游戏消息服务

**职责：** 处理游戏内的通用消息路由。

## 数据库层

### DataBaseService

```
Init():
  ├─ 构建 DbConfig (server, port, user, password, database)
  ├─ DatabaseFactory.CreateDatabase(config, MYSQL)
  ├─ database.Open()
  └─ 连接失败时：database = null，使用临时数据运行
```

### ConnectionPool

- 连接池大小：5
- 管理 MySqlConnection 的复用
- 支持 getConnection() / closeConnection()

### IDatabase 接口

```
Query(table, columns, selection, selectionArgs, groupBy, having, orderBy)
Insert(table, nullColumnHack, values)
Update(table, values, whereClause, whereArgs)
Delete(table, whereClause, whereArgs)
ExecSQL(sql)
```

## 事件通信

服务间通过 `EventService` 和 `ServiceEventDefine` 通信：

```
ServiceEventDefine:
  c_playerJoin   — 玩家加入游戏
  c_playerExit   — 玩家退出游戏
  c_playerLogin  — 玩家登录

GameUtils:
  c_gameFinish   — 游戏结束
  c_scoreChange  — 分数变化
```
