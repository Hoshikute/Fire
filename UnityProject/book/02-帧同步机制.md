# 帧同步机制

## 设计思想

本项目实现了**预测-回滚式帧同步**：客户端不等待服务端确认，先用本地预测执行逻辑，收到服务端权威数据后若发现预测错误则回滚重算。这种方式在保证确定性的同时大幅降低了操作延迟感。

核心原则：
1. 固定时间步长（默认 50-100ms），保证确定性
2. 所有游戏逻辑只在 FixedUpdate 中执行
3. 服务端权威——服务端的帧数据是最终裁决
4. 客户端预测——本地立即执行输入，后续验证

## 服务端帧驱动

### UpdateEngine

独立线程，固定时间间隔驱动所有 World 更新。

```
UpdateEngine.Init(intervalTime = 50ms)
  └─ new Thread(UpdateLogic)
      └─ while(true)
          ├─ deltaTime = GetServiceTime() - lastTime
          ├─ if(deltaTime >= IntervalTime)
          │   └─ UpdateWorld(deltaTime)
          │       └─ for each world in WorldManager.WorldList
          │           └─ world.FixedLoop(deltaTime)
          └─ Thread.Sleep(remainTime)
```

服务端只调用 `FixedLoop()`，不调用 `Loop()`。

### 命令收集与广播

```
客户端发送 Command
    ↓
CommandMessageService.ReceviceSyncMsg()
    ├─ 发送 AffirmMsg (确认收到)
    ├─ ConnectionComponent.AddCommand(cmd)
    └─ ControlSpeed() → 可能发送 PursueMsg

PlayerInputSystem.BeforeFixedUpdate()  (每帧执行)
    ├─ 遍历所有玩家实体
    ├─ cmd = connectionComp.GetCommand(world.FrameCount)
    │   └─ 无命令时使用预测（复制上一帧）
    ├─ entity.ChangeComp(cmd)
    └─ 广播 CommandMsg 给所有客户端
```

## 客户端帧驱动

### WorldManager

```
Unity Update()
  ├─ s_UpdateTimer += Time.deltaTime * 1000 * updateSpeed
  ├─ UpdateWorld()  // 逻辑帧（表现层）
  │   └─ world.Loop(deltaTime)
  └─ while(s_UpdateTimer >= IntervalTime)
      ├─ s_UpdateTimer -= IntervalTime
      └─ FixedUpdateWorld(IntervalTime)  // 同步帧
          └─ world.FixedLoop(IntervalTime)

Unity LateUpdate()
  └─ world.LateUpdate(deltaTime)  // 渲染后处理
```

`updateSpeed` 由服务端 PursueMsg 控制，实现追帧/减速。

### 客户端命令发送

```
CommandSyncSystem.NoRecalcBeforeFixedUpdate()
  ├─ 自身实体:
  │   ├─ BuildCommand(comp)    // 从 InputSystem 构建输入
  │   ├─ entity.ChangeComp(comp)
  │   ├─ RecordCommand(comp)   // 记录到历史
  │   └─ SendCommand(comp)     // 发送到服务端
  └─ 其他实体:
      └─ 从服务端缓存获取或预测（复制上一帧）
```

## 追帧机制（Pursue）

### 速度调整算法

服务端根据客户端帧号与目标帧的差距动态调整速度：

**目标帧计算：**
```
advanceFrame = RTT / IntervalTime + 1  (限制在 2~7)
aimFrame = serverFrameCount + advanceFrame
```

**客户端过快（需减速）：**
```
领先 >= 16帧 → speed = 0.5
领先 >= 8帧  → speed = 0.65
领先 >= 4帧  → speed = 0.75
领先 >= 2帧  → speed = 0.85
领先 >= 1帧  → speed = 0.95
```

**客户端过慢（需加速）：**
```
落后 >= 32帧 → speed = 16
落后 >= 16帧 → speed = 8
落后 >= 8帧  → speed = 4
落后 >= 4帧  → speed = 1.5
落后 >= 2帧  → speed = 1.25
```

### PursueMsg 交互

```
服务端 ControlSpeed()
  ├─ 计算 speed
  ├─ 若 speed 变化 → 发送 PursueMsg(speed, advanceCount, recalcFrame)
  └─ 更新 connectionComp.UpdateSpeed

客户端 RecevicePursueMsg()
  ├─ 发送 AffirmMsg 确认
  ├─ 若有 recalcFrame → 触发 Recalc()
  └─ 保存 aheadFrame（调整虚拟时间乘数）
```

## 回滚重计算（Recalc）

### 触发条件

1. 收到服务端命令与本地预测不一致
2. 收到 PursueMsg 中的 recalcFrame
3. 收到 SyncEntityMsg（服务端强制同步实体状态）

### 重计算流程

```
SyncSystem.Recalc(frameCount)
  ├─ 1. RevertToFrame(frameCount - 1)    // 回退到确定帧
  ├─ 2. ClearAfter(frameCount - 1)       // 清理未来快照
  ├─ 3. for i = frameCount to currentFrame:
  │     ├─ m_world.IsCertainty = (i == frameCount)
  │     ├─ world.Recalc(i, IntervalTime)  // 重新执行逻辑
  │     ├─ ExecuteServiceMessage(i)        // 应用服务端数据
  │     └─ world.Record(i)                 // 重新记录快照
  ├─ 4. ClearBefore(frameCount - 2)       // 清理旧快照
  └─ 5. ClearFrame = frameCount - 2       // 更新确定帧标记
```

### 确定性保证

- `IsCertainty = true` 的帧：服务端已确认，不会再回滚
- `ClearFrame`：此帧之前的所有数据已确定，可安全清理快照
- 只有预测帧中创建/销毁的实体会被记录和回滚

## 命令一致性检验

```
客户端收到服务端广播的 CommandMsg
  ├─ 比对本地预测与服务端命令 (EqualsCmd)
  ├─ 若一致 → 标记确认，派发 isAllMessage 事件
  └─ 若冲突 → 触发 Recalc(conflictFrame)
```

## 调用链总览

### 服务端时序

```
UpdateEngine Thread
  └─ FixedLoop(deltaTime)
      ├─ PlayerInputSystem: 收集命令 + 广播
      ├─ 游戏逻辑 System 执行
      └─ ServiceSyncSystem: 同步实体变化

Network Thread
  ├─ CommandMessageService.ReceviceSyncMsg(): 接收客户端命令
  └─ CommandMessageService.ReceviceAffirmMsg(): 更新 RTT
```

### 客户端时序

```
Unity Main Thread
  ├─ FixedLoop(IntervalTime)
  │   ├─ Record() → 保存快照
  │   ├─ CommandSyncSystem: 构建并发送命令
  │   ├─ 游戏逻辑 System 执行（与服务端一致）
  │   └─ EndFrame()
  │
  └─ Network Message Dispatch
      ├─ ReceviceCommandMsg() → 验证/回滚
      ├─ RecevicePursueMsg() → 调速/回滚
      └─ ReceviceSyncEntity() → 强制同步
```
